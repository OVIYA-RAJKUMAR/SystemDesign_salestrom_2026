# ADR-007: Transactional Outbox Pattern for Asynchronous Event Delivery

## Context
If payment succeeds but Order Service or Message Broker fails immediately afterwards, payment state and order state become inconsistent.

## Decision
We implement the **Transactional Outbox Pattern**. `OutboxEvent` records are inserted into the database inside the exact same database transaction as the payment status update.

## Rationale
Ensures at-least-once event publication even during abrupt process termination. The Order Service consumer processes outbox events idempotently upon recovery.
