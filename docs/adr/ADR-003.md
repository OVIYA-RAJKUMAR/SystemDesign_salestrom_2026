# ADR-003: Atomic Conditional Update vs Optimistic Locking

## Context
When 10,000 requests hit Product X simultaneously, updating inventory requires choosing between Optimistic Locking with version numbers or Atomic Conditional SQL updates.

## Decision
We select **Atomic Conditional Update** as the primary reservation strategy:
`UPDATE inventory SET available = available - 1, reserved = reserved + 1, version = version + 1 WHERE product_id = ? AND available >= 1`

## Rationale
Optimistic locking causes massive version mismatch retries under high contention (9,900 failed version checks). Atomic conditional update leverages row-level DB locks to complete in a single atomic pass with zero overselling.
