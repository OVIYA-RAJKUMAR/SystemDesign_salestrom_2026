# ADR-001: Microservices vs Modular Monolith Architectural Boundary

## Context
SALESTORM requires scaling flash-sale operations to 10,000 req/s while preserving clear domain boundaries between Inventory, Payment, and Order management.

## Decision
We select a **Modular Microservices Architecture** with decoupled domain services and an event-driven outbox pipeline.

## Rationale
Decouples inventory consistency checks from external payment gateway latencies and background order fulfillment.

## Consequences
Requires outbox event publishing and idempotency key enforcement across service boundaries.
